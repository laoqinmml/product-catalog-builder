# 步骤 1：输入与素材盘点

目标：在动手排版之前，把「有什么、缺什么、谁提供」一次说清。这一步的产出是**素材清单 + 缺口列表**，不是版面。

## 输入是什么

把用户给的一切都先落地到 `root/` 之外的一个素材暂存目录，再分拣。常见输入：

| 输入类型 | 处理方式 | 落到哪里 |
| --- | --- | --- |
| 产品照片（手机拍的、工厂给的） | 按型号命名，进步骤 3 清洗 | `assets/` 待定 |
| 已有 300 DPI 大图 / 官方渲染图 | 直接可用 | `assets/` 待定 |
| 规格表（Excel / Word / PDF） | 抽成结构化文本，做页面文案底稿 | `tmp/specs/` |
| 旧画册 PDF | 拆页、抽文字、抽图，当参考不当素材 | `tmp/old-catalog/` |
| 品牌 VI / logo / 色值 | 直接可用，锁定品牌色与字体 | `assets/brand/` |
| 资质证书扫描件 | 只做版面呈现，不裁掉可核验信息 | `assets/certs/` |

## 盘点动作

1. 列出**型号清单**。图册的产品页是按型号排的，型号是主线。缺型号 = 缺页。
2. 每个型号核对四件套：主图、细节图、规格表、卖点文案。缺哪件记哪件。
3. 核对图片的**实际像素**，不看文件大小。A4 整幅图需要 ≈ 2480 × 3508 px（210 × 297 mm @ 300 DPI）。一张 800 px 宽的图放大到整幅就是必然的模糊。
4. 核对**底色**。版面上只允许两种底：白色和品牌藏青 `#101A3D`。抠好的透明 PNG 将来按所在底色合成，所以现在就要知道每张产品图会被放在哪种底上。
5. 记下**不确定的事实**。证书编号、成立日期、产能、认证名称这类必须可核验，不许编。查不到就留空并在缺口列表里标注「待用户确认」。

## 快速盘点命令

```powershell
# 工程目录树（先看清楚结构）
Get-ChildItem -Recurse -Directory -Depth 2 $root | Select-Object FullName

# 图片实际像素分布（需要 Python + Pillow）
py -3 -c "import sys,glob; from PIL import Image; [print(Image.open(p).size, p) for p in glob.glob(sys.argv[1]+'/**/*.*', recursive=True)]" $root

# 型号清单：从规格表抽型号列
rg -o "\bTW[- ]?[0-9]{2,4}\b" $root/tmp/specs
```

## 输入 → 输出的分拣规则

- 会出现在版面上的图 → `assets/`（合并 HTML 里的路径是 `assets/...`，单页里写 `../assets/...`）。
- 只在做图阶段用、不上版面的参考图 → `tmp/refs/`，绝不放 `assets/`，否则会被 `build_print_sources.py` 当成版面素材一起重做。
- 旧画册拆出来的图 → `tmp/old-catalog/`。**旧画册里的图经过一次压缩，通常够不上 300 DPI，不要直接搬进 `assets/`。**

## 检查点（进步骤 2 之前必须过）

- [ ] 型号清单完整，且每个型号都知道要占几页。
- [ ] 每张计划上版面的图都 ≥ 目标尺寸的 300 DPI 像素。
- [ ] 每张抠图都知道将放在白底还是藏青底。
- [ ] 所有「硬事实」（日期、编号、认证、产能）都有来源，没有来源的已列入缺口列表。
- [ ] 缺口列表已交给用户，或已明确决定用占位符先排版。

## 常见坑

- **拿网页图当素材。** 网页导出的图为了加载快都压过，放大就是糊。要图就问供应商要原图。
- **素材混进 `assets/`。** 一旦进去，导出 PDF 时会被逐张重做，白耗时间还把体积做大。
- **先排版再找图。** 素材缺口是排版的输入，不是排版的副产品。缺口没清就排版，等于把返工写进流程。
