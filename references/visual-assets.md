# 步骤 3：视觉资产生成与清洗

目标：把步骤 1 收来的原始素材，做成 `assets/` 下**尺寸达标、底色干净、命名规范**的上版图。产物是图片文件，不是版面。

## 输入是什么

步骤 1 的素材暂存目录，加上步骤 2 的页序表（决定每张图放多大、放什么底）。

## 尺寸怎么定

按**版面实际占用尺寸**倒推像素，不要凭感觉给大图：

```
目标像素宽 = 版面宽度(mm) / 25.4 × 300
```

- A4 竖版整幅（210 × 297 mm）≈ 2480 × 3508 px。
- 半幅图就按半幅算，不要给整幅像素——给大了 PDF 体积白涨。
- 只缩不放：源图小于目标尺寸时，宁可换源图，也不要用脚本放大（放大出来的图在 PDF 里一放大就糊）。

## 底色与抠图

版面上只允许两种底：**白色**和品牌藏青 `#101A3D`。

- 产品抠图（去背后的透明 PNG）最终会被 `build_print_sources.py` 按所在底色合成 JPEG，所以现在就要确定每张图放在哪种底上。
- 合成 JPEG 的好处：PDF 里不用塞带透明遮罩的 PNG，体积小、不出白边。
- **例外**：图片自身或祖先元素带 `filter` / `opacity` < 1 / `mix-blend-mode`（例如封底 logo 用 `invert` 变白）时，合成到背景色会算错，这类图**保留透明 PNG**，不要预合成。

## 允许和不允许的编辑

可以：去背、补光、超分、统一背景、轻微校色、去水印。

不可以：改外形结构比例、改镀膜颜色、加不存在的零件、用 AI 图替代真实产品图。产品图是事实陈述，不是插画。

## 命名与落位

- 文件名用型号或用途，全小写，短横线分隔，例如 `tw-302-front.png`。
- 上版面的图放 `assets/`；只在做图阶段当参考的图放 `tmp/refs/`。
- 单页 HTML 里引用写 `../assets/...`（因为页面在 `pages/` 下一层），合并脚本会自动改成 `assets/...`。

## 大批量清洗

用 Pillow 批量处理时，逐张处理而不是全塞进内存：

```powershell
# 统计现有素材的实际像素，找出不达标的
py -3 -c "import sys,glob; from PIL import Image; [print(Image.open(p).size, p) for p in glob.glob(sys.argv[1]+'/**/*.*', recursive=True)]" $root/assets
```

抠好的透明 PNG 不用手动合成——交给 `build_print_sources.py`，它读版面测量结果按真实绘制尺寸重做。手工合成的图尺寸往往和版面实际不符，反而会触发放大。

## 检查点（进步骤 4 之前必须过）

- [ ] `assets/` 里每张图的实际像素 ≥ 它在版面上占用尺寸的 300 DPI。
- [ ] 每张抠图都确定了白底还是藏青底，需要保留透明的已标注。
- [ ] 文件名统一小写、短横线分隔，无空格无中文括号。
- [ ] 没有「旧画册拆出来的压缩图」混进 `assets/`。
- [ ] 参考图、过程文件没有混进 `assets/`。

## 常见坑

- **拿网页图当素材。** 网页导出的图都压过，放大就是糊。要图就问供应商要原图。
- **参考图进了 `assets/`。** 一旦进去，导出时会被逐张重做，白耗时间还把 PDF 体积做大。
- **手动预合成透明 PNG。** 合成尺寸凭猜，和版面实际不符，容易触发放大或裁切。让流水线按测量结果合成。
